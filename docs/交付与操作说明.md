# 交付与操作说明

## 范围

本文覆盖当前 M7 的本地/受控环境交付。按本次交付要求，**不提供、不执行 Docker Compose 部署**。PostgreSQL 16 + pgvector 应由受控环境预先提供。

## 环境变量

复制根目录 `.env.example` 为 `.env`，并至少设置下列真实值：

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL asyncpg 连接串。 |
| `JWT_SECRET` | 至少 32 个字符的 JWT 密钥。 |
| `ENCRYPTION_KEY` | Fernet 格式密钥，用于环境密钥和 LLM Key 加密。 |
| `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` | 首次启动时创建管理员；密码至少 12 个字符，二者必须同时设置。 |
| `SOURCE_ROOT_ALLOWLIST` | 本地源码允许根目录，多个目录以英文逗号分隔。 |
| `OPENAPI_HOST_ALLOWLIST` | OpenAPI URL 的允许 Host，多个 Host 以英文逗号分隔；支持 `*.example.com`。 |

以下变量可按环境容量和策略调整：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `APP_ENV` | `development` | 应用环境标识。 |
| `FRONTEND_ORIGIN` | `http://localhost:5173` | 前端来源配置。 |
| `SOURCE_UPLOAD_ROOT` | `data/source-uploads` | ZIP 与 OpenAPI 上传文件的受控保存目录。 |
| `DEFAULT_REQUEST_TIMEOUT_SECONDS` | `20` | 单次接口请求超时秒数。 |
| `MAX_RESPONSE_BODY_BYTES` | `1048576` | 单次响应正文上限。 |
| `EXECUTION_MAX_CONCURRENCY` | `5` | 单进程执行器最大并发连接数，范围为 1-20。 |
| `MAX_SOURCE_ARCHIVE_BYTES` | `524288000` | ZIP 源码包大小上限。 |
| `MAX_SOURCE_FILE_BYTES` / `MAX_SOURCE_FILE_COUNT` / `MAX_SOURCE_TOTAL_BYTES` | 见 `.env.example` 与配置默认值 | 单文件、文件数和总源码读取上限。 |
| `MAX_OPENAPI_DOCUMENT_BYTES` | `5242880` | OpenAPI 文档大小上限。 |
| `EMBEDDING_DIMENSIONS` | `1536` | 当前 pgvector 维度，必须保持 1536。 |
| `EMBEDDING_MODEL` / `EMBEDDING_BATCH_SIZE` / `EMBEDDING_MAX_ATTEMPTS` / `EMBEDDING_TIMEOUT_SECONDS` | 见 `.env.example` | 向量生成配置。 |
| `KNOWLEDGE_CONTEXT_MAX_RESULTS` / `KNOWLEDGE_CONTEXT_MAX_CHARACTERS` / `KNOWLEDGE_VECTOR_CANDIDATE_COUNT` | 见 `.env.example` | 混合检索上下文上限。 |
| `AGENT_LLM_TIMEOUT_SECONDS` | `60` | 单次 LLM 调用超时秒数。 |

`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` 保留在 `.env.example` 供外部 PostgreSQL 初始化信息使用；当前 M7 交付不通过 Docker Compose 管理数据库。

## 初始化与启动顺序

以下命令是交付操作步骤，执行前应取得相应环境授权。

1. 确认 PostgreSQL 16 + pgvector 可访问，且 `.env` 中的 `DATABASE_URL` 正确。新数据库需先由
   PostgreSQL 超级用户执行 `CREATE EXTENSION IF NOT EXISTS vector;`，业务用户不负责安装扩展。
2. 空数据库选择一种方式初始化，不能同时执行：

   - 推荐在 `backend/` 安装依赖并执行全部 Alembic 迁移：

     ```powershell
     uv sync
     uv run alembic -c alembic.ini upgrade head
     ```

   - 也可以直接在空数据库执行 `deploy/sql/001_init_business_schema.sql`。该脚本与
     `0018_add_execution_traceability_snapshots` 对齐，并会写入 `alembic_version`；执行成功后无需再运行既有迁移。

3. 启动后端：

   ```powershell
   uv run uvicorn app.main:app --reload
   ```

4. 首次启动时，如不存在同名用户且已同时配置 `INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD`，系统会创建管理员；已存在用户不会被覆盖。未配置这两个变量时，系统跳过初始化管理员。
5. 在 `frontend/` 安装依赖并启动管理台：

   ```powershell
   pnpm install
   pnpm dev
   ```

6. 使用 `/health` 确认后端可访问，再以初始化管理员登录。

## 源码扫描操作

1. 管理员创建项目，语言固定为 Java、框架固定为 Spring Boot。
2. 配置源码：本地目录必须位于 `SOURCE_ROOT_ALLOWLIST`；ZIP 不得含绝对路径、`..` 路径或符号链接条目。
3. 配置 OpenAPI：文件会保存到受控上传目录；URL 必须匹配 `OPENAPI_HOST_ALLOWLIST`，且不能解析到私网或保留地址。
4. 在“接口管理”发起扫描，观察 SSE 进度直至成功。
5. 在接口详情核对源码符号、OpenAPI 定义与冲突信息。每次扫描生成独立 `scan_version`，旧用例和报告不会被新扫描覆盖。

## 用例、执行和报告操作

1. 在“AI 分析”选择扫描版本和接口，使用已启用 LLM 配置生成用例。
2. 在“用例管理”核对请求模板和断言；在 Agent 审核操作中将用例置为 `approved`。`draft`、`pending_review`、`disabled` 用例不能执行。
3. 配置测试环境：Base URL Host 必须写入 `host_allowlist`；生产环境不能执行；写请求还必须启用 `allow_write_requests`。
4. 在“执行中心”执行单用例或批量用例。涉及 POST、PUT、PATCH、DELETE 时，确认弹窗中必须确认当前完整目标 Host。
5. 在“测试流程与报告”按顺序配置已审核用例和变量提取规则，执行登录、创建、查询、修改、删除等关联链路。
6. 在报告中查看脱敏请求、响应、断言、变量、cURL、失败诊断及“可追溯证据”；失败可按入口重新执行。流程重试从第一步开始以重建运行变量。

## 交付检查

1. Alembic 已升级到 `0018_add_execution_traceability_snapshots`。
2. `.env` 未提交，真实密钥未写入文档、日志或报告。
3. `OPENAPI_HOST_ALLOWLIST` 与 `SOURCE_ROOT_ALLOWLIST` 已按目标环境配置。
4. 按 [MVP 验收用例](MVP验收用例.md) 完成 AC-001 至 AC-005。
5. 按需执行 `uv run ruff check .`、`uv run mypy app`、`uv run pytest`、`pnpm typecheck` 和 `pnpm build`；本次代码修改未自动执行这些命令。
